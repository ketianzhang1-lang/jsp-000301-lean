## Execution protocol and trust boundary

The workflow prepares official toolchains and dependencies in a disposable Docker image based on `rust:1.90.0-slim-bookworm`. It then runs original verification, official target checks and replay/export without network access, as UID 10001, with all capabilities dropped, no-new-privileges, four CPUs, 14 GiB memory, 24 GiB combined memory/swap and 1024 processes. The host workflow provisions 16 GiB swap. Only disposable proof and evidence directories are writable; harness inputs and the prepared external tools are read-only during offline checks. No account credentials or user home directory are mounted.

Lean 4.34.0 / Mathlib `5ed2965256430c3649e86755f9576b54eca72435` apply to 636, both 912 layouts, 393, 728 and 585. The two 506 groups use Lean 4.31.0 / Mathlib `fabf563a7c95a166b8d7b6efca11c8b4dc9d911f`. Each project retains its own original lockfile and all nine dependency pins; no `lake update` is permitted.

The harness removes project build outputs before the submitted complete verifier and uses no resume option. Trusted pinned Mathlib caches may be reused; the compiler and all Mathlib are not rebuilt from first principles. Each explicit target and auditor bridge must receive source checking, `#check`, full `#print`, and transitive `#print axioms`. Kernel replay uses the fixed Lean toolchain's own checker; it is not a separately implemented proof kernel. Independent NaNoda checking uses exported complete target dependency closures with only `propext`, `Classical.choice` and `Quot.sound` permitted and a hard error for unpermitted axioms.

**Exporter compatibility is explicitly a harness adaptation.** Exporter source `6cea97789dc088ea47fcea15692db85685aedac5` originally pins **Lean 4.35.0-rc2**. The harness copies the reviewed project's **4.34.0** toolchain file into the disposable exporter checkout and rebuilds it. We must describe this as that source rebuilt for compatibility, not as a natively 4.34-pinned exporter release. Actual build and export success must be evidenced; it cannot be assumed from the source revision. The 506 exporter `8554815c2dc6b7abe99ec1f08849c9759ba77947` originally pins 4.31.0, matching those projects. NaNoda source is fixed at `4c544ed4099c8227f07d5de77ad1e69fb0740a27` and built with Cargo's locked dependencies.
